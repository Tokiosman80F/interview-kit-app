Primitives are copied by value; objects are copied by reference

Copy a primitive and you get a second, separate value. Copy an object and you get a second arrow pointing at the same object.

Think of it like this

Primitive = a photocopyI photocopy my notes and give you the copy. If you scribble on yours, mine stays clean.
Object = a shared Google Doc linkI send you the link. If you edit the doc, I see the edit, because there is only one doc.

Primitives: string, number, bigint, boolean, undefined, null, symbol. Everything else is an object: plain objects, arrays, functions, dates.

Watch it happen

Step 1 of 3: create

The same thing in code

let a = 5;
let b = a;      // b gets its own 5
b = 10;
console.log(a); // 5   (a did not change)

const user = { name: "Ann" };
const copy = user;      // copy points to the same object
copy.name = "Bob";
console.log(user.name); // "Bob"   (user changed too!)

The same happens when you pass an object to a function: the function gets the arrow, not a copy, so changing a property inside the function changes the caller's object.

function rename(person) {
  person.name = "Mia";
}
rename(user);
console.log(user.name); // "Mia"

How to get a real, separate copy

const copy = { ...user };     // new object, one level deep
copy.name = "Bob";
console.log(user.name);       // "Ann"   (user is safe)

const list2 = [...list];      // same idea for arrays
const deep = structuredClone(user); // copies every nested level too

Spread only copies the top level. Objects nested inside are still shared. You will meet this again in Level 3: shallow copy vs deep copy.

Why interviewers ask this

React decides whether to re-render by checking if the new state is the same object as the old one. If you change the state object directly, it is still the same object, so React sees no change:

// Wrong: same array, React does not re-render
items.push(newItem);
setItems(items);

// Right: a new array
setItems([...items, newItem]);

Say it in one sentence: "Primitives are copied as values, so the copy is independent; objects are copied as references, so both variables point to the same object, and changing it through one shows through the other."

Check yourself

Say your answer out loud, then open it.

1. let x = "hi"; let y = x; y = "bye"; What is x?

"hi". Strings are primitives, so y got its own copy.

2. const a = [1]; const b = a; b.push(2); What is a?

[1, 2]. a and b point to the same array.

3. Why is { id: 1 } === { id: 1 } false?

Each { } creates a new object. === checks whether both sides are the same object, not whether they look the same.
